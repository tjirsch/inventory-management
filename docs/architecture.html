Factory Inventory Management System

A demo full-stack app: a Vue 3 single-page dashboard backed by a FastAPI service that serves mock data from JSON files held in memory. There is no database, and no authentication.

System architecture

Three tiers on one machine. The browser talks directly to the API over HTTP. There is no proxy.

Tech stack

Minimal dependencies on both sides. Charts are hand-written SVG, so there is no chart library.

Frontend

  • Vue 3 (Composition API)
  • Vue Router 4 (web history)
  • axios for HTTP
  • Vite 8 dev server and build
  • Custom SVG charts, CSS Grid

Backend

  • Python 3.11+
  • FastAPI
  • Pydantic v2 models
  • Uvicorn ASGI server
  • uv for env and dependency management

Data

  • Static JSON fixtures
  • Loaded once at import time
  • generate_data.py regenerates fixtures
  • Read-only. Nothing is persisted.

Cross-cutting

  • i18n: English and Japanese, locale saved in localStorage
  • Currency: USD or JPY follows the locale
  • Tests: pytest + TestClient in tests/backend
  • Scripts: scripts/start.sh, stop.sh

Data flow: a filter change

This is the main interaction loop. All four global filters live in one shared composable, and every view reads from it.

User picks a filter

FilterBar writes to singleton refs in useFilters

View reacts

The view watches the refs and calls getCurrentFilters()

api.js

Drops 'all' values and builds query params

FastAPI route

apply_filters then filter_by_month run over in-memory lists

Pydantic

response_model validates and serializes the result

Render

Raw data goes into refs. Computed properties derive KPIs and charts.

Filter mapping: Time Period → month, Warehouse → warehouse, Category → category, Order Status → status. Inventory has no time dimension, so it ignores month.

Worth knowing

These came up while reading the code. They are observations, not changes.
  • Filters are only partly global. Demand, backlog, spending, and reports endpoints ignore the filter bar, so changing a filter only affects Dashboard, Inventory, and Orders.
  • The dashboard backlog count ignores filters. total_backlog_items is always len(backlog_items).
  • Month filtering is a substring match. month in order_date works for full YYYY-MM values, but a partial value like "01" would also match the day part. Quarters are hard-coded to 2025.
  • Backlog view is unrouted. views/Backlog.vue exists but is not registered in main.js.
  • Hard-coded API URL. http://localhost:8001/api appears in api.js and again in Reports.vue. There is no env config and no Vite proxy.
  • Read-only data. JSON is loaded once at startup and no route writes to it. Editing a fixture requires a server restart to take effect.
